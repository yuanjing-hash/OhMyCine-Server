# 媒体库准备状态与整理任务明细

媒体库列表通过 `ready` 与 `readiness_status` 显示服务端准备状态。所有本地和云端媒体库共用此契约。首次扫描/检查尚未完成时显示初始化状态；检查发现问题但用户没有提交物理整理时，问题数量不代表业务不可用。只有提交实际整理、凭据失效、来源不可用或未确认完成的文件操作才会阻止相关正常业务。预览和人工选择不触发物理操作。

准备状态包含 `ready/disabled/unavailable/credentials_required/repairing/repair_failed/busy/initializing/checking`。凭据更新和原任务恢复入口在未准备好时仍须可用。凭据恢复只解除凭据问题；部分失败的整理须完成核验和恢复，不能由 Cookie 保存直接宣告修复成功。

部分失败不等于任务永远占用媒体库。成功项已经入库、失败项的实际位置已经核验且文件操作许可完成收尾后，失败明细保留，但不阻挡重新诊断和新整理；用户重试原任务时仍只处理剩余项。结果不明的移动、改名或云端回收不能仅凭失败计数、任务取消或文件缺失宣告完成。

“已停用”控制自动业务，不等于取消用户已提交的操作。初始化、首次检查或停用自动监听期间，只允许具有精确持久任务归属的扫描后续、诊断及已接纳文件任务完成；不能仅凭任务类型放行。凭据失效、竞争中的修复或未确认文件操作仍优先拦截，原任务恢复按归属核验。

115 Cookie 更新必须验证是原来的同一账号。保存成功后立即采用返回的连接 revision 并清空输入；只改 Cookie 不再提交没有改变的数据源目录更新，避免再次触发目录核验和物理操作阻塞。若同时修改目录而目录保存失败，已保存的凭据和新 revision 仍保留，用户重试只提交尚未完成的部分。

## 任务明细 API

`GET /api/v1/jobs/:id/repair-details?page=1&page_size=50&status=` 返回标准响应信封，data 包含 `list/total/page/page_size/phase/counts/current_action/current_item/current_batch_size`。

`status` 可留空或为 `all/pending/running/succeeded/failed/blocked`；`all` 与留空等价。`counts` 是整个整理任务各状态数量，`total` 是筛选后的数量。每页默认 50，允许 1–200；页大小只限制单次读取，不限制任务项目总数。按 ordinal 稳定排序，计数与页面使用独立 SQL 查询。

条目仅包含序号、操作、媒体种类、安全库内相对来源/目标、状态、安全错误和更新时间。不返回私有冻结计划、Provider ID、租约、Cookie、绝对磁盘根。访问同时要求任务读取权限与对应媒体库读取权限；所有结果和拒绝响应均 no-store。

当前操作在外部调用前按租约写入，批量调用明确显示本批项目数和代表项目，不能假称知道批次内哪一项先完成。进程退出后只有仍在运行的任务才投影当前操作；成功数量必须以核验后的检查点为准。每项结果属于同一个 Job，不创建逐文件子任务。原媒体库失败项 API 保留 failed/blocked 语义。

`busy` 表示 Server 正在自动核验先前文件操作的结果，不是等待用户确认，也不是线程名额不足。管理端必须写明“无需手动确认”并提供任务中心入口；核验成功后原排队任务自动继续，不创建替代任务。v101 使用通用正向证据收口旧 receipt-v0 的零写入产物任务：仅删除 `queued` 且空指纹的数据库占位并将 physical evidence 收口为 `settled`；任何真实产物、写入回执、cleanup claim、已写计数、租约或身份不匹配都必须继续阻挡。

`GET /api/v1/jobs/:id/timeline` 和 `/attempts` 支持 `page/page_size`，返回 `list/total/page/page_size`，最新记录优先；旧记录始终可分页读取。任务抽屉显示中文状态、独立的项目分页和历史分页；后台刷新保留用户页码/过滤条件，旧请求不得覆盖新选择。整理明细在抽屉打开时每 5 秒更新，关闭即停止。

## 日志参考

任务列表和详情另提供 `wait_reason {code,message}`，说明当前可确认的媒体库阻塞或预定重试时间，与上次执行错误分开显示。不会猜测未知的并发占用原因，也不返回无权查看的阻塞任务身份。

取消尚未执行的整理后，精确的未执行记录不再让媒体库永久停在修复中。媒体产物已经执行过、退出到等待重试或暂停后才取消的，由后台分页核验原文件结果；原任务仍为已取消，不继续剩余整理，不生成逐文件任务。旧记录证据不足、来源变化或文件内容冲突时保留安全限制并说明核验障碍，不能把“已取消”直接等同于“文件操作已确认”。

目录整理在运行中取消时，先停止后续物理操作，等待已经发出的调用退出，再核对并保存实际结果。暂停或失败退出后才取消的任务，复用现有后台维护按页收尾，不创建替代任务。核验只观察、不移动、不改名、不回收；原任务保持已取消。停止期间若原路径出现了其他文件或目录索引身份已变化，不能用旧计划覆盖新条目。正常生命周期不依赖一次性的测试数据清理脚本，也不新增旧版本迁移流程。

参考 MoviePilot 的同一进度记录更新和 115 STRM 助手的阶段/结果分离：任务内解释准备、移动、核验和待恢复阶段，同时展示成功、失败和待执行数量。详见工作区研究记录固定上游版本。文件明细读取持久检查点，不追加逐项 INFO 日志，不复制上游包含 Provider ID 或原始错误的日志内容。
