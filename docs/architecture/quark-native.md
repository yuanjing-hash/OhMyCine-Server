# 夸克原生连接与媒体同步

夸克在 Server 中是一个连接。TV 与官方 Open/Agent 是内部能力分工，媒体库、下载器、Player 和 STRM 使用同一个连接及现有媒体流水线。此文描述代码中的合同；真实客户端验收状态见文末，不能用构建或模拟测试代替实际播放验收。

## 授权与能力

| 工作 | 使用路线 | 当前能力边界 |
| --- | --- | --- |
| 目录读取、文件定位 | TV | 分页读取；目录分页不是原子快照 |
| 原文件播放 | TV | 只取原文件下载地址；鉴权成功后返回 302 |
| 建目录、移动、重命名、上传 | Open/Agent | 需要管理授权、共同空间证明和持久操作收据 |
| 分享预览 | 客态分享协议 | 真实目录与文件选择，凭证固定 provider |
| 选择文件转存 | Agent 接收 | 确认实际目标，转成 TV 身份后进入整理 |
| 普通复制、回收与恢复 | Web 候选 | 本轮未作为可用能力开放 |
| 云离线下载 | 独立能力 | 未开放，不进入 BT 下载候选 |

正常连接的核心是 TV 播放授权和 Agent 管理授权。它们不是同一令牌，也不从另一套凭据推算出来；不把三个适配器变成必须三次扫码。Web 不属于当前核心登录流程。

Player 的 `playback_check_v1` 在夸克条目通过权限、来源和原文件解析检查后，可附带固定 `http_read_profile: "bounded_ranges_v1"`。客户端按单文件采用有限 8 MiB HTTP Range，仍直接读取相同 TV 原文件；该提示不包含任意引擎选项、临时直链或账号头。未支持此读取策略的客户端继续原播放路径，其他媒体来源不带该提示。最终流请求仍重新鉴权，Server 不承载播放视频体。

TV 授权码兑换及续期默认使用 `https://api.extscreen.com/quarkdrive/token`。该服务会经手 TV 授权码或刷新令牌，并返回 TV 访问令牌。这不是夸克第一方令牌服务。已有 Web/Agent 凭据不发送给它。前端只接收当前授权步骤及功能状态，授权包加密保存，正常同身份续期不会改变连接配置代际。

TV 与 Agent 的令牌更新共用连接级互斥与同一密文版本的 CAS。令牌兑换结果先持久保存，再核验身份；核验暂时失败后，下一次使用继续确认这份检查点，不重新消费刷新令牌。核验仍绑定原账号身份，一个未就绪接口不会使另一套已验证授权失效。

TV 和 Agent 的账号 ID、文件 ID 保留各自命名空间。共同空间验证在选定根下写入极小随机文件，再由 TV 独立定位并读取内容，保存根范围的共同访问证明。该证明不等于官方账号等价声明。更换账号、授权身份或验证根后，旧证明不再适用。

目录与媒体清单采用 TV 身份。管理写操作前重新定位对应 Agent 身份；写完后独立映射回 TV，检查父目录、名称、类型和大小。不能把一种接口的 ID 直接交给另一种接口，也不能只凭相同文件名认定同一文件。

## 播放与文件传输分开

```text
Player / Emby / STRM
    → OhMyCine 权限、签名和目录资格校验
    → TV 原文件地址解析
    → HTTP 302
    → 客户端直接读取夸克文件
```

STRM 保存 Server 的签名播放地址，不保存临时直链。播放时再解析当前地址，临时链接过期不要求重建全部 STRM。现有签名有效期、密钥轮换和用户权限仍然生效。

TV 的下载元数据不能证明文件所在父目录。冷启动播放按当前有效媒体目录中的相对路径，从库根逐级读取真实目录，并核对最终 TV 文件 ID；签名 STRM 从版本化目录取定位，不能以旧锚表路径或进程内缓存代替。路径同名替换、重复名称和不完整分页都会拒绝本次解析。

播放失败不会自动切到转码视频、Server 视频代理或 Node 视频代理。需要额外账号 Cookie 的响应不能冒充纯 302。临时链接及凭据不写入日志、目录清单或公开任务详情。

原文件302正确性与持续播放性能分别验收。小范围字节匹配、成功打开视频和会员状态都不能代替实际吞吐、拖动和持续播放检查；发现请求范围相关的低速时保留性能未通过结论，不将增加缓存或切换传输路线当作同一合同已通过。

上传、跨盘复制和 Node 文件搬运可以传输媒体字节，这是文件任务的数据流，和上述播放路径不同。

## 变化观察代替生活事件

系统不把夸克目录差异伪装成生活事件。只观察明确配置的媒体库根及启用的接收根，维护持久的范围、批次、条目和目录队列。每个目录只比较直接子项。

本系统的已确认转存和整理目标经 `ReconcileTransferBatch` 发布，直接推动识别、目录、STRM 和刷新，不等下一次巡检，也不启动整库递归扫描。其他明确写入结果可以保存到观察批次。外部修改由目录巡检发现，日志说明是巡检观察到的变化。

默认调度目标如下。这些数值是产品请求预算，不是夸克公布的安全速率，也不构成任意规模下的更新时效保证。

| 目录或工作 | 默认目标 |
| --- | --- |
| 已确认的本系统操作 | 立即处理；同目录补充检查合并 5 秒 |
| 自动接管接收根 | 约 1 分钟 |
| 近 30 分钟变化目录 | 约 2 分钟 |
| 普通库根 | 约 15 分钟 |
| 冷目录 | 后台轮转，目标 24 小时覆盖 |

每账号一个观察读取请求并发、请求间隔至少 2 秒、每小时最多 600 次观察请求；热、冷目录各预留一半额度，空闲时借用。分页工作每轮最多 5 页或 15 秒让出调度；本地确认与路径修复也分批执行。限流冷却同时约束该连接的交互访问、授权和播放解析请求。展示待检查目录、待确认缺失、待发布变化、错误及下一次重试时间，不能将延期当成已同步。

首次扫描、立即同步和定时核对共用这套队列。分页返回可以先贡献可信的新增和更新；页数、数量或身份不一致的读取不能作为删除证据。进程重启后，未读完目录从第一页重新确认；已完成读取后的本地确认阶段按持久游标继续，不重复读取云端页面。

目录改名或移动使用稳定身份修复关系，再分批更新后代路径。观察发布只提交确定的正向变化及有证据的精确下架 ID，不给普通巡检设置会裁剪未见条目的 `AuthoritativeParentPaths`。

完整父目录观察确认旧子目录不再可达时，单独记录不可达分支证据，并分批传播到已知后代目录。它们不再永久阻塞覆盖队列，也不伪造子目录已完整读取；下架仍须独立复查和整个可达范围覆盖。若同一身份在另一目录出现，清除不可达标记并重新排队检查后代。

## 缺失、下架和恢复

首次缺项只形成候选。自动下架要求同账号空间、范围和配置代际下至少两轮独立完整观察，间隔至少 10 分钟，并完成当前范围覆盖以排除移动到其他目录；可靠定位证据可用于直接核实移出范围。分页失败、授权失败、读取不完整和未完成写操作都不能据此清库。

下架先撤销媒体和旧产物的播放资格，再排队清理归属可确认的系统产物，不删除夸克文件。迟到的清理执行前重新检查代际。恢复证据保存至少 30 天；稳定资源身份与历史关联不跟随恢复明细一起删除。

已观察条目保存绑定源代际、根和范围的媒体身份恢复证据。文件恢复或在库内移动时可继续使用原媒体身份、入库时间和有效人工识别，不按历史路径猜测原记录。仅 catalog head 正常前进不会使这种证明失效；更换账号或根则会失效。

确认下架的事务在替换目录版本前保存当前最新条目及人工识别恢复证据，并在同一事务撤销精确归属 STRM 的播放资格。产物 worker 尚未执行时，旧签名及已缓存直链的解析也必须拒绝；磁盘清理由既有精确工作清单执行。恢复后的新代际产物不会被迟到的旧清理删除。相同 ID、名称和大小的恢复仍需重新发布事实与产物；只有随后真正无变化的巡检才按无操作处理。

没有可靠版本、摘要且名称、大小、时间均未改变的内容替换无法保证由元数据巡检发现。观察器不会为弥补这一限制后台下载整个媒体库计算 hash。

## 写操作、上传和 Node

持久操作收据固定接口路线和操作身份，私密请求内容加密保存。请求结果不明时核对原操作，不切换到另一接口重新提交。恢复路径不把“上游已接受”当作文件已经入库。

Agent 改名的提供方批次号是单独持久化的16位十六进制值，不直接使用Server的长任务ID。必须先保存批次号及提交意图，再发请求；旧收据不因缺少此字段而补发。提交错误只保留安全数字HTTP状态和业务errno，未取得明确完成证据时仍保持结果未知，不根据HTTP400自行重提。

改名和移动丢失回执时，使用已冻结的原文件身份、目标名称/父目录及完整目录读取核对实际结果，确认后继续原收据。目录创建或分享接收缺少可归属的输出身份时继续保留结果不明，不能只凭同名文件认领完成或重新发起写操作。已观察 TV 父链仅能作为管理映射的路径提示，最终必须重新核验原 TV ID，防止把同路径的新文件当成旧文件。

分享接收任务同时冻结接收目录身份和相对路径。本地恢复使用这份快照；下载器后来改选另一目录不会改变已创建任务的目的地。冷启动以保存的 Storage 显示根和相对路径作提示，逐级完整读取并独立验证根及目标身份，再做 TV/Agent 映射，不遍历旁边的目录树。提示不等于权限或身份依据，同名替换、路径越界及 Storage 变更均拒绝。

同盘整理只在已验证能力范围内移动或改名，确认最终 TV 身份后写入本批目标清单。普通复制和回收未开放，因此不提供依赖回收的覆盖处理。跨盘来源为夸克时，未具备可靠回收能力的跨盘移动在选路及执行阶段拒绝；可以采用保留云源的复制。

已管理任务的版本化重新整理复用同一 TV/Agent 映射和操作收据，每次修改前持久保存当前操作游标。确认等待不消耗普通失败重试额度；授权失效或结果不明使用任务的“重新核对”动作。写入开始后，观察保护持续到已确认目录发布，在失败、取消或进程恢复时也不靠丢弃收据解除。最终事务一次性提交 Catalog、确认观察基线及后续产物状态，不再调用另一观察入口重复发布。它保留已接受任务的既有权限语义：用户主动重试或响应动作时重新鉴权，不宣称每一步都会因后来撤权而停止。

本地或 qBittorrent 输出上传到夸克后，完整读取 TV 原文件并比较 SHA256，确认后才发布目录。上传重启不会只凭同名同大小文件认领成功，而是继续原持久操作，并完成读回。目标的完成记录保存 `version=2 / sha256 / full_readback` 摘要。旧 115 SHA1 校验路径保持原合同。

原生 `ResolveUploadReadbackItem` 只为当前已确认上传返回待完整校验的目标候选。它重新核对原收据、账号及共同根证明、Agent ACK/list 和新鲜 TV 位置、类型、大小、修订与绑定摘要；已有映射不能当成当前内容证明。首次跨接口映射已完成时，可以省掉紧邻最终核验之前的重复内容读取，使正常新上传由三遍目标读取降为两遍。Server 最终完整 SHA256 校验及 Node 读前／读后的身份、唯一位置、修订、租约和授权检查保持不变。一般 `ResolveReadItem` 与不满足条件的冷恢复继续严格校验，结果不明不产生第二次上传。

文件传输的完整读取按连续 8 MiB 闭合 Range 流式进行，逐段检查状态、范围、总长与实际字节数，最终仍核对完整文件摘要；不把分段可读当作整文件一致。取消会中止正在等待的网络读取，不缓存整部视频。分片上传的前缀 SHA1 在同次执行中增量计算，避免为每个分片重复读取整个前缀；冷恢复仍重新核实原输入与持久收据。

夸克来源下载到受管暂存时计算 SHA256 并持久化，重新启动先核对已确认暂存文件。没有可信版本的未确认分片从头读取，避免把两个版本拼接成一个文件。读取有大小上限、磁盘空间预留和任务心跳；确认后再交给原有本地整理或目标上传流程。

Node 必须声明对应读取、分享接收、上传和摘要版本能力。任务冻结根目录、动作、文件清单、目标路径和摘要；授权只更新受限凭据，不改变任务身份。旧 Node 在选路或提交前明确拒绝，不在执行失败后把媒体流量切回 Server。

Node 续期采用同一任务和范围的密封授权。驱动在构造上游请求前安装新访问令牌；续期不能加入刷新令牌、Web 会话、其他动作或根目录。长时间上传和读回持续检查持久任务租约，撤销或过期会中止阻塞的 I/O，保留原操作用于核对。离线令牌切换测试与真实独立 Node 云传输分别记录，不能互相替代。

## 验证边界

隔离回归覆盖了持久观察、分页异常、重启、缺失复查、身份恢复、目录改名、限流、公平调度、收据 CAS、同盘整理、上传读回和跨盘暂存。还运行了真实服务代码链：转移目标清单 → 版本化目录 → 后续任务 → 产物 worker → 磁盘签名 STRM。这里的云端接口使用测试提供方，不能据此声称线上大文件或真实客户端已验收。

正式交付仍需单独保存真实 Player 与 Emby/STRM 播放、不同公网出口、Range/拖动、音轨和外挂字幕证据，并确认 Server/Node 不承载播放字节。Web 普通文件/非空目录复制、回收恢复、永久清理和云离线未验收，不应在界面标为已支持。发布与运行中部署是独立操作。
