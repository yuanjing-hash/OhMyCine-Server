# 已确认入库后的源文件策略

`SeedingTaskSummary` 和公开 `JobDTO` 增加可选的 `purpose`：

- `source_cleanup`：源文件收尾；移动入库及所有跨数据源上传网盘的任务使用此用途。
- `seeding`：继续沿用本地复制等现有做种策略。

内部 Job 类型、队列、原 Job ID 和 `seeding-tasks` 路径保持兼容。`purpose` 由下载任务的冻结移动方式、数据源身份和传输路线推导，前端不能通过修改此值授权删除。旧客户端可以忽略此字段。身份和路线的私有 JSON 不会返回给客户端。

移动一律不保种；上传网盘一律不保种，包括复制。移动在目标文件确认及本批目录发布后清理其受管源；上传网盘的复制只结束原下载器任务，保留源文件。其它本地复制继续使用冻结的做种策略，软链接继续保护源文件。不根据提供方品牌、主机名或 Node 所在位置选择策略。

同源本地移动已经移走文件，因此原下载器移除使用 `delete_data=false`。Node 移动或上传移动只有完整清单证明无受保护剩余文件时才允许请求整包清理。普通 Node 包无法精确清理且存在受保护剩余文件时，结束原下载器任务并记录 `protected_source_retained`，不扩展为递归删除。云端复制记录 `copy_source_retained`。这些状态不表示任务仍在做种。

共享文件选择仍由原 group 收据负责精确清理。完成的无保种引用先退出消费者状态；其它消费者仍在使用时，原收尾任务显示 `cleanup` / `shared_source_retained` 并继续核对同一收据，不重新下载、上传或创建新收据。共享物理清理延期不算本任务做种。

读取、认证或会话失败时不提交删除。保留安全错误码、原 Job 和历史，用户修复连接后使用普通 Job `retry`。Job 查询在权限允许时把旧的“做种：作品”投影为“源文件清理：作品”，不修改历史记录。日志分别表示核对原任务、计划清理以及上游已接受的清理请求；接受请求不等于证明所有字节已删除。

源清理使用共享选集的只读检查及原清理收据，不调用会创建下载的 union Apply。引用退役不会伪造新的 applied revision/digest；原 native hash 消失时不会重新提交种子。所有消费者已经退役后，qB 适配器在原收据和归属校验下停止原任务再清理，`ProbeOnly` 不发新的暂停或删除请求。此适配器由 Server 和 Node 共同使用，交付需同步更新两侧二进制，节点协议保持兼容。

新的普通源清理完成事实保存在原 Job 私密 checkpoint 的 `source_cleanup_confirmed` 中，v1 绑定原 download、transfer 和 `managed_revision`，与源收尾状态在同一事务提交。该字段不属于公开 DTO，不能从旧版仅清理接收暂存的 `completed` 推断此事实。迟到的 native-missing 或受保护源保留结果不会覆盖本轮已有的真实完成事实。
