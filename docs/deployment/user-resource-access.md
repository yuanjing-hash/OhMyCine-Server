# 用户资源权限

进入 **用户管理 → 账户**，选择一个用户，在 **权限设置** 中调整这个用户可以使用的资源。所有新用户和未配置的现有用户默认四项全部开放；角色和功能权限继续生效。

| 设置 | 控制内容 |
| --- | --- |
| 下载器使用 | 可查看/使用的下载器，以及分享预览、下载和转存的下载器选择 |
| 站点搜索 | 可查看、搜索并使用结果的 PT、公开 BT 和网盘分享站 |
| 媒体库访问 | 媒体库列表、作品、搜索、图片、播放，以及相关历史/合集投影 |
| 媒体库入库 | 新建下载、订阅与整理任务的目标库；还必须允许访问该库 |

每项可选三种模式：

- **全部开放**：不增加资源限制，仍需对应功能权限。
- **白名单**：只有选中的资源可用。未选任何资源时全部禁止；后来新增的资源也默认禁止。
- **黑名单**：选中的资源禁止，其余可用。未选任何资源时全部允许；后来新增的资源也默认允许。

例如，某用户只允许使用「本地 qBittorrent」，将下载器使用设为白名单并选中它；只允许访问「家庭电影库」则将媒体库访问设为白名单并选中该库。如果还要允许下载到该库，媒体库入库也要允许它。名单不代替角色：只读角色即使名单全部开放，仍不能提交下载。

当前有效权限仍遵守直接拒绝优先规则。资源名称旁会显示当前生效结果和原因；修改模式/选择后点击保存才生效。若其他管理员先保存，页面提示版本冲突并保留草稿，重新加载后再编辑。Owner 和自己的授权不可通过该页面修改；受限管理员不能授出自己没有的资源权限。

修改后的新请求立即按新名单执行，搜索结果和直接链接也重新检查。已经提交的下载/入库继续原有计划；手动重试、新任务和下一次订阅运行需要重新授权。订阅保留原先选中的站点，后续搜索只使用仍允许的站点；没有可用资源时明确失败，不显示成没有匹配内容。历史只保留安全阶段摘要。

Server 网页和连接到 Server 的 Player 使用同一套服务端判断。Player 独立连接的其他数据源使用自己的访问权限。

生成的媒体库和分类封面包含实际影片海报，读取旧封面地址也需要登录并检查当前库权限；内置通用图标和插件自带静态封面仍可公开读取。Player 同步使用受保护图片地址和登录请求，不把令牌放在 URL 中。

旧下载任务若没有保存可核实的站点来源，在用户站点权限收紧后不能直接手动重试，需要重新搜索后提交；原先已提交的后台任务继续执行，不会因此被重置。

## API v1

使用现有认证与标准 `{code,message,data}` 响应格式。查看需要 `users.read`，保存需要 `roles.assign`，并继续执行受保护账户、管理员授予边界和 CSRF 等检查。

```text
GET /api/v1/users/:id/resource-access
GET /api/v1/users/:id/resource-access/options
PUT /api/v1/users/:id/resource-access
```

策略读取及保存结果：

```json
{
  "revision": 1,
  "policies": [
    {"scope": "downloader_use", "mode": "all", "resource_ids": []},
    {"scope": "site_search", "mode": "all", "resource_ids": []},
    {"scope": "library_read", "mode": "all", "resource_ids": []},
    {"scope": "library_ingest", "mode": "all", "resource_ids": []}
  ]
}
```

PUT 一次提交四个唯一 scope 和读取到的 revision。版本过时返回 `CONFLICT`，不会覆盖其他修改；未知范围、模式、无效新资源或每项超过 1000 个 ID 的名单返回 `INVALID_REQUEST`，拒绝整个保存。站点和媒体库 ID 统一为十进制，重复 ID 去重；旧的已删除引用允许保留或移除。全部开放的 resource_ids 必须为空。超出操作者自身授权范围的净新增权限返回 `PRIVILEGE_ESCALATION`。

options 返回 revision 与 scopes 数组，每项包含 scope、resource_type 和 options，每类最多读取 2000 个资源。资源选项只有 `id/name/type/status/deleted/effective_allowed/can_grant/denial_reason`；不会返回账号凭据。`effective_allowed` 表示当前已保存策略与功能权限合并后的判断。删除或不可查看的已保存引用使用占位显示。

本功能新增策略表但不改写旧授权规则，不重置历史任务；部署更新按标准数据库迁移执行。
