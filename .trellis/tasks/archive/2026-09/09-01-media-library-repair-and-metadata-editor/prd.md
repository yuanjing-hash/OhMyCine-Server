# 修复批量下载并增加媒体库结构修复与完整元数据编辑

## Goal

修复下载管理页轮询覆盖用户表单的问题，支持换行批量提交链接；为已有本地/115 媒体库提供可审计、可恢复的目录结构诊断与修复，并把作品详情的元数据维护提升为可编辑完整元数据与图片的管理界面。

## Requirements

- 下载页后台状态刷新不得清空用户已选择的下载器、目标媒体库、来源模式或已输入内容。
- URL/磁力与 115 分享输入按非空行解析，一行一个链接，最多 50 条；逐条返回成功/失败，失败行保留在表单中以便修正，不重复提交成功行。
- 媒体库首次完成扫描后自动执行只读结构诊断，不自动移动文件；发现异常时在媒体库管理页提示修复。
- 用户可按整个媒体库或单个作品发起修复。没有选择首次全库修复时，后续同一 TMDB 作品有新内容入库前自动修复该作品的旧布局。
- 电影与电视剧都使用当前 Profile 命名模板，且固定根始终为 `电影` / `电视剧`；电视剧按 `Season NN` 归档。
- 修复覆盖视频以及同目录关联字幕、NFO、海报等伴随文件，完成后删除媒体库根以内已经为空的旧目录，但绝不删除非空目录或媒体库根。
- 本地与 115 使用同一 provider-neutral 计划器，并通过各自的严格 backend 执行移动/改名；每次执行前重验来源身份、大小、目标冲突和媒体库边界。
- 未识别作品、结构异常、修复运行中和修复失败均在 Server 媒体库页面可见；错误仅展示稳定错误码和安全相对路径。
- 作品详情可编辑标题、原名、日期、简介、标语、状态、评分、时长、类型、国家、语言、工作室、导演、编剧、演员及 TMDB 图片选择。
- 手动识别继续复用现有媒体识别/人工覆盖边界；客户端不能直接伪造 TMDB 身份。元数据编辑由独立服务类校验并写入识别快照，触发现有 NFO/JPG/STRM 与媒体服务器刷新链路。
- 所有写操作沿用权限、审计、队列、路径约束和 115 风控/限流边界。

## Acceptance Criteria

- [ ] 下载页连续轮询至少两次后，用户选择与输入保持不变；只有所选下载器/路线确实失效时才回退。
- [ ] 多行输入可创建多条任务，空行被忽略，重复行被提示且不重复创建，超过 50 条或包含非法行时得到明确结果。
- [ ] 首次扫描只报告结构问题，不改变来源文件；UI 可查看问题数量和安全样例并显式发起修复。
- [ ] 本地和 115 测试均证明旧式剧集目录可迁移到 `电视剧/<分类>/<剧名 (年份)>/Season NN/`，字幕/元数据跟随且空旧目录被清理。
- [ ] 新季入库前只修复同一已识别作品，不扫描/移动其它作品；修复失败会阻止新内容形成第二套目录并给出可重试状态。
- [ ] 未识别、结构异常和修复失败可在媒体库页面筛选/查看。
- [ ] 元数据编辑可保存完整字段和可选图片，重新加载仍保留；重新扫描不会覆盖人工编辑，清除人工覆盖后恢复自动识别。
- [ ] 修改元数据后沿用现有权威变更、媒体产物和通知机制。
- [ ] Go/WebUI 测试、类型检查、Lint、生产构建、`go vet` 和 `git diff --check` 通过。

## Notes

- 不实现任意外部图片 URL 或浏览器直传到数据源；本期图片编辑选择经过 Server 校验的 TMDB 图片身份，避免把管理端变成任意 URL/文件写入入口。
- 结构修复是移动/改名与空目录收敛，不永久删除媒体文件。
