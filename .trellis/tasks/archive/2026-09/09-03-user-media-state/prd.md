# Server 用户历史、收藏与自动合集

## Goal

让连接 OhMyCine Server 的 Player 拥有可验证、可分页、按用户隔离的观看历史与收藏，并在媒体库首次扫描和后续完整/增量扫描完成时，依据已落库的 TMDB 电影合集元数据自动建立和维护合集；同时允许用户创建和管理自己的合集。

## Requirements

- Player 本地保存播放进度后应在短延迟内触发 Server 同步，离线时仍以本机记录为安全后备。
- Server 保留现有增量同步协议并提供完整观看历史分页读取能力；同步和读取均按认证用户隔离。
- 同步失败不能被完全静默吞掉，Player 应保留脱敏、可诊断的最近同步状态。
- 收藏是用户私有状态；同一媒体可被不同用户独立收藏或取消收藏。
- Server 提供收藏列表、单项状态查询和幂等设置接口，Player 的 Server 数据源接入现有收藏页与媒体动作。
- Server 提供用户私有的手工合集，允许创建、列出、添加成员、移除成员和删除。
- 自动合集只针对已成功识别且带有效 TMDB `belongs_to_collection` 的电影，不把同一作品的多个媒体版本重复计数。
- 自动合集在首次扫描成功提交时生成；后续非 partial 扫描对受影响媒体库进行幂等对账。
- 默认至少有两部已入库电影时显示/建立自动合集，与 Emby/Jellyfin Box Set 的默认行为一致；单片合集候选可保留为不可见派生事实以支持后续增量补齐。
- 自动成员和用户手工成员必须记录来源。扫描只增删 `tmdb` 派生成员，绝不覆盖或删除用户手工合集及其成员。
- TMDB 上游标识、海报/背景文件标识可持久化；不得保存 TMDB 凭据、临时 URL 或 Player 的流地址。
- Player 在没有 Server、Server 版本较旧或离线时继续使用现有本地历史与本地收藏/合集。

## Acceptance Criteria

- [ ] 播放 Server media-entry 超过本地保存阈值后，2 秒调度窗口内会尝试 `/api/v1/player/history/sync`，无需等待 60 秒轮询。
- [ ] 两个用户写入相同媒体身份后，只能读取各自的历史和收藏。
- [ ] Server 历史分页按最近更新时间稳定排序，可在 Player 历史页选择 Server 查看并继续播放。
- [ ] Server 数据源可收藏/取消收藏，收藏页能列出 Server 收藏。
- [ ] 用户可在 Player 现有合集交互中创建 Server 合集并添加媒体，重启后仍存在。
- [ ] 首次完整扫描中，同一 TMDB collection 的两部不同电影会自动生成一个合集；一个电影的多版本不重复。
- [ ] 后续非 partial 扫描会补入新电影并移除已经离库的 `tmdb` 自动成员；partial 扫描不以缺失为删除证据。
- [ ] 自动对账不会修改或删除任何用户手工合集/手工成员。
- [ ] TMDB collection 元数据有边界校验和测试，数据库迁移可重复验证且不破坏现有 v59 历史数据。
- [ ] API、Player 类型检查、Server Go 测试和相关构建检查通过。

## Constraints

- Server 与 Player 仅通过版本化 HTTP 合约集成，Player 基本播放不依赖 Server。
- SQLite 为默认数据库，关联写入使用事务。
- 当前 Server 工作区存在另一个 Trellis 任务的未提交修改；本任务不得覆盖或提交那些文件。
