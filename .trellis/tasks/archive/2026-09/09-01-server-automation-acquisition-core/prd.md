# Server 自动化、权限与搜索入库核心

## Goal

把 Server 的搜索、下载入库、媒体库修复、权限和定时执行收敛为一套可追踪、可授权、可恢复的服务端能力，并为 Player 提供安全、渐进式的搜索入库接口。

## Requirements

### 1. 细粒度权限

- 内置角色仅作为创建角色时的模板；管理员可以创建、保存和复用自定义角色。
- 支持对单个用户直接配置允许和拒绝，最终权限为“角色允许并集 + 用户允许 - 用户拒绝”，拒绝优先。
- 权限支持全局和资源范围，首批资源范围覆盖媒体库、下载器和站点。
- 增加 Player 连接、发现搜索、创建入库、订阅和媒体库管理等明确能力；Player Bootstrap 必须按当前用户动态返回能力。
- 路由中间件和服务层都做权限校验；前端隐藏按钮不构成授权。

### 2. 搜索与入库状态

- 按 TMDB 身份建立统一 acquisition 状态，持续记录搜索、已选择资源、下载、整理、入库、失败、订阅和媒体库覆盖情况。
- Player 和 Server Web UI 读取同一份状态；再次打开同一海报时可看见当前阶段和最近失败。
- 下载器、目标媒体库、分类规则和订阅参数在最终确认时冻结，任务重试不得悄悄改用新的默认值。

### 3. 多站点渐进搜索

- 所选站点使用受控并行，而不是逐站等待；不得为每次请求创建无限 goroutine。
- Server 使用跨请求共享的全局并发上限，并继续遵守每站点现有限流；每个站点有独立超时和取消上下文。
- 单站失败或超时不取消其他站点；客户端断开必须停止仍可取消的工作。
- 标题多语言别名在单站内保持有界、去重并遵守站点节流。
- SSE 同时支持普通标题搜索和 TMDB 多语言聚合搜索，并发送 metadata、progress、site、done/error 事件。
- progress 至少包含 total、pending、running、completed、succeeded、failed、result_count 以及刚发生变化的站点安全标识/名称/状态。
- 最终结果按站点优先级、站点 ID 和现有资源排序规则稳定排序，不受 goroutine 完成顺序影响。
- 搜索结束后能查看失败站点并单独重试；已成功站点的结果不被清空。

### 4. 媒体库目录诊断和修复

- API 拆分为读取最近结果、主动诊断、预览、确认修复和历史运行；读取接口不得暗中启动扫描。
- Server 媒体库页始终提供“检查目录结构”，并支持手动诊断、预览后修复。
- 修复遵循已配置媒体库分类路径：`电影/<分类>/<作品>` 与 `电视剧/<分类>/<作品>/Season NN`，不是把作品直接放在 `电影` 或 `电视剧` 根下。
- 本地和 115 共用同一诊断/计划模型、不同驱动执行器；修复是移动语义，成功后旧受管源文件不得残留副本。
- 新位置元数据成功生成后，清理旧位置的 inactive managed NFO/图片/STRM，再自底向上删除空作品目录和空分类目录。
- 未托管文件绝不自动删除，必须作为残留显示在预览/结果中。
- Windows 本地文件操作区分 sharing violation 与 ACL denied；文件占用有限退避重试，并提供目录 create/rename/delete 能力探测，不盲目重写整库 ACL。
- 修复或清理尚未完全结算时不得标记 completed/healthy。

### 5. 统一五段 Cron 调度

- 所有可配置定时任务统一保存标准五段 Cron、IANA 时区和 enabled；UI 是 Cron 可视化生成器而不是另一套调度格式。
- 提供分钟、小时、每日、每周、每月和高级 Cron，Server 负责严格解析并预览未来运行时间。
- misfire、重叠/并发、重试和最大运行时间作为 Cron 之外的执行策略单独保存。
- 迁移追更、媒体库全量扫描、CookieCloud、115 回收站清理、目录诊断、可选目录自动修复、STRM/本地元数据一致性检查。
- 115 生活事件、队列心跳、下载器轮询、上传心跳和 UI 刷新等常驻循环不迁移为 Cron。

## Non-goals

- 不在本任务中改变普通 Player 的离线播放独立性。
- 不自动修复未托管文件，不自动重置 Windows 目录 ACL。
- 不移除现有非流式 JSON 搜索接口；它继续作为兼容接口并复用同一协调器。

## Acceptance Criteria

- [x] 权限矩阵测试覆盖角色模板、用户允许、用户拒绝、拒绝优先、资源范围和服务层绕过尝试。
- [x] Player Bootstrap 不再返回写死 capability，未授权用户不能搜索、下载入库、订阅或管理媒体库。
- [x] acquisition 状态可在 Server 重启后恢复，并能由 Player 按 TMDB 身份读取。
- [x] 至少 8 个假站点的测试证明并发不超过配置上限、确实存在并行、单站超时隔离、取消生效且最终排序稳定。
- [x] SSE 测试覆盖完整进度单调递增、result_count 聚合、部分失败、单站重试和无凭据/上游正文泄漏。
- [x] 普通 JSON 搜索与 SSE 最终投影一致。
- [x] 目录修复测试证明视频、字幕和受管元数据被移动，旧受管 NFO/目录被清理，未托管文件保留并报告。
- [x] Windows sharing violation 重试与 ACL denied 诊断具有独立错误码，运行未结算时不会显示 healthy。
- [x] Cron API 能解析/拒绝五段表达式、按时区预览未来运行、处理 misfire/重叠/重试并完成现有定时配置迁移。
- [x] Server Web UI 提供权限编辑、统一计划任务、主动目录检查/预览/修复和搜索进度/失败重试界面。
- [x] API 架构契约、权限目录、迁移与相关 Trellis spec 同步更新，Server 全量质量门通过。
